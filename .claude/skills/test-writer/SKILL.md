변경한 동작을 검증하는 테스트를 쓰고, 실제로 실행해서 통과하는지까지 확인한다.

## 1. 테스트 방법부터 찾는다

새로 정하지 말고 프로젝트가 쓰는 방식을 찾는다.

- 프로젝트 지침(`CLAUDE.md` 등)에 적힌 테스트 명령과 규칙
- 설정 파일의 스크립트 (`package.json`, `Makefile`, `pyproject.toml` 등)
- 기존 테스트 파일의 위치, 이름 규칙, 사용하는 도구와 작성 스타일

찾지 못하면 추측해서 도구를 들이지 말고 사용자에게 묻는다.

## 2. 무엇을 검증할지 정한다

- **동작**을 검증한다. 구현이 어떻게 생겼는지가 아니라 입력에 대해 어떤 결과가 나와야 하는지를 본다.
- 정상 경로 하나로 끝내지 않는다. 경계값, 빈 값, 잘못된 입력, 실패 경로를 포함한다.
- 테스트 하나는 한 가지만 확인한다. 이름만 읽어도 무엇이 깨졌는지 알 수 있게 짓는다.
- 시간, 난수, 외부 서비스처럼 흔들리는 것은 고정하거나 대체해서 결과가 매번 같게 한다.

## 3. 작성하고 실행한다

1. 기존 테스트의 스타일과 구조를 따라 쓴다.
2. 가능하면 구현 전이나 수정 전에 **먼저 실패하는 것**을 확인한다. 실패하지 않는 테스트는 아무것도 증명하지 못한다.
3. 구현이 끝난 뒤 통과하는 것을 확인한다.
4. 관련 없는 테스트가 깨지지 않았는지 전체 테스트를 실행한다.

## 지킬 것

- 테스트를 통과시키려고 **테스트의 기대값이나 구현을 왜곡하지 않는다.** 실패 원인이 실제 코드의 버그라면 고치고 보고한다.
- 깨진 테스트를 지우거나 건너뛰도록 바꾸지 않는다. 그렇게 해야 한다면 사용자에게 먼저 묻는다.
- 실행하지 않은 테스트를 통과했다고 말하지 않는다.

## 보고

- 추가하거나 고친 테스트: 파일과 무엇을 검증하는지
- 실행한 명령과 결과: 통과와 실패 개수
- 실패나 건너뜀: 있다면 원인과 다음 선택지
- 검증하지 못한 부분: 테스트로 확인하지 못해서 남는 위험
